# Troubleshooting：失败模式与升级复测

每条给出：**症状 / 诊断 / 安全动作 / 危险 workaround（禁止）**。

---

## 1–4：安装路径失败

### 1. Tap 已注册但 Skill 不被索引

- **症状**：`tap list` 有该 tap，`search` 命中 0 条。
- **诊断**：先确认库层（library）能否解析同一 source；能解析 = 本机 CLI/索引限制，不是仓库问题。
- **安全动作**：记录为 `CLI / indexing limitation`，改走 direct URL 或 external dirs。
- **禁止**：为迁就 CLI 去改 Skill 仓库结构 / 改名 / 挪目录。

### 2. Library 层可解析但 CLI 失败

- **症状**：直接读取 source 可以拿到元数据与内容，但 CLI 的 search / inspect 报找不到。
- **诊断**：对比同一标识符在两层的结果，确认差异发生在解析层而非网络/内容。
- **安全动作**：作为本机限制记入报告，选其它官方机制；升级后复测。
- **禁止**：反复绕圈试参数、伪造本地副本充当安装结果。

### 3. Direct URL 被 URL safety 拦截

- **症状**：安装/检查时报被拒绝或「不安全 URL」。
- **诊断**：看日志里的判定原因（私网、协议、重定向目标）。
- **安全动作**：记 `network / safety-layer blocker`，改用官方支持的替代机制。
- **禁止**：关闭 URL safety、放宽网络策略、绕过权限。

### 4. Fake-IP / 私网段拦截

- **症状**：目标域名被解析到保留/私网网段，请求被按私网地址拦下。
- **诊断**：解析结果 + 安全层日志。
- **安全动作**：识别为环境层问题（DNS 被接管/代理层介入），记录并改用不依赖该网络路径的官方机制。
- **禁止**：把安全层判定当成「应该关闭的障碍」。

## 5–8：source 与内容完整性

### 5. 多文件 Skill 半安装

- **症状**：入口能加载，但 references / scripts / linked files 缺失或为空。
- **诊断**：逐个列举声明与实际（入口引用 vs 磁盘/安装结果），做双向比对。
- **安全动作**：按失败处理并重做接入；或改用能整体消费目录的机制（external dirs）。
- **禁止**：只验证入口就宣布成功。

### 6. external dir 指向过期 checkout

- **症状**：本机加载到的内容落后于 canonical（章节缺失、版本陈旧）。
- **诊断**：比较本地 HEAD 与远端默认分支；确认无本地领先提交。
- **安全动作**：`fetch` → 确认 clean → **fast-forward**；然后重新取证。
- **禁止**：`reset --hard`、覆盖本地改动、手工挑文件同步。

### 7. external dir 指向 dirty 工作树

- **症状**：`git status` 有未提交改动，或位于开发分支。
- **安全动作**：**STOP**，报告并询问；不要覆盖用户改动。
- **禁止**：`clean -fd`、强制同步、把工作副本当 canonical。

### 8. 同名 local Skill 覆盖 canonical

- **症状**：加载到的内容来自旧本地副本；`inspect` 的 source 指向本地目录。
- **诊断**：清点同名副本（含 archive/retired），确认优先级与生效项。
- **安全动作**：按退役流程把旧副本移出活动路径（保留备份），再重新验证生效项。
- **禁止**：靠改名规避冲突、在两处同时维护内容。

## 9–11：加载与运行时

### 9. 装了但没真正加载

- **症状**：文件/登记都就位，但索引里没有或取到的是旧内容。
- **诊断**：三层分别取证（文件层 / 新进程 / 运行中进程）。
- **安全动作**：按运行时新鲜度流程刷新（重建 prompt / 新会话 / 新进程）后重新验证。
- **禁止**：以「文件存在」为完成判据。

### 10. references 缺失

- **症状**：入口声明的 references 打不开，或磁盘上有未被引用的孤儿文件。
- **诊断**：入口/README 引用集合 vs 磁盘文件集合做双向比对。
- **安全动作**：确认 canonical 仓库侧双向一致；若仓库侧一致而本机缺失 = 接入不完整，重做接入。
- **禁止**：在本机手工补文件（会形成第二份 source）。

### 11. 运行中进程仍是旧索引

- **症状**：新进程能看到新 Skill，当前会话/服务看不到。
- **诊断**：对比新进程与运行中进程的索引结果。
- **安全动作**：记录 `Runtime refresh: REQUIRED`，在合适时机刷新（优先新建会话而非重启服务）。
- **禁止**：为验证而无必要地重启生产服务。

## 12–14：身份与安全

### 12. 临时工作目录被当成 canonical source

- **症状**：external dir / 安装来源指向 scratch、缓存、打包解压目录或 PR 工作分支。
- **诊断**：Source Inventory 中该路径的类型判定。
- **安全动作**：改为指向干净 canonical checkout（默认分支、clean、up to date）。
- **禁止**：让「工作副本」长期充当 source。

### 13. canonical 未验证就退役旧 Skill

- **症状**：旧 Skill 已移走，canonical 却不可加载或身份不一致。
- **诊断**：回查退役门逐条状态。
- **安全动作**：先回滚（临时恢复旧 Skill），修复 canonical 接入后重新退役。
- **禁止**：在 canonical 未验证时继续扩大退役范围。

### 14. Hermes 意外改写了 canonical checkout

- **症状**：external source 的工作区出现非预期改动。
- **诊断**：检查本机实现的写入路径（curation / sync / update），并在验证前后对比 `git status`。
- **安全动作**：`STOP`，做安全评估（文件系统只读 / 权限隔离 / 独立用户）；必要时停用 external dirs。
- **禁止**：忽略该现象继续跑。

## 运行时新鲜度速查

| 状态 | 证明 | 需要刷新吗 |
|------|------|-----------|
| 文件已写入 | 读文件 | 不适用 |
| 配置已改 | 解析配置 + 读回该键 | 不适用 |
| 新进程可加载 | 新进程索引/检查命令 | 不需要 |
| 运行中进程可加载 | 当前服务实际索引 | 若否 → 需刷新 |

优先刷新手段：**重建 prompt / 新会话 / 新起进程**；重启生产服务需先说明影响与必要性。

## Hermes 升级后的复测流程

```
1. 记录新版本与 `skills` / `tap` 子命令的 help 输出（能力面可能变化）
2. tap:      tap list → search → inspect → install（逐个实测）
3. direct URL:   用默认分支官方 URL 测试安装链路是否仍被安全层拦截
4. external dirs: 复测发现 / 加载 / 只读性行为是否变化
5. 选择最简且官方的机制
6. 若官方 tap 恢复：完成完整验证（发现 / inspect / 实际加载 / references / shadowing）后再从 external dirs 切换
7. 切换后复查 canonical checkout 未被 Hermes 改写、旧路径已退役
```

原则：**workaround 会过期**。每次升级都应重新评估，而不是把某一版的变通做法固化成长期方案。
