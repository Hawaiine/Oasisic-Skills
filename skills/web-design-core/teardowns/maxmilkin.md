# maxmilkin.com 深度拆解

> 渲染方式：真实 Chromium 渲染（CDP）。桌面 1440×900，移动 390×844（DPR 2），实测时间 2026-11-05。
> 站点栈：CRA（`/static/js/main.*.js`）+ **Lenis** 平滑滚动 + **three.js**（4 个 WebGL canvas）。
> 滚动机制：**无劫持**。桌面用 `position: sticky` 钉住 hero（`.hero__wrapper { position: sticky }`，section 高 2070px / wrapper 900px），移动端把 `.scroll-container` 变成 `overflow:scroll` 的内部滚动器（clientHeight 844 / scrollHeight 8127）。桌面与移动的 `scrollY` 均实测可推进，截图均为真实滚动位置。

## 2. Token 实测

### 2.1 字体

- 字体族：**RF Dewi**（display + UI 全部角色）、**Bebas Neue**（存在，用于局部窄体标签）。全站只有 2 族。
- 字重：**300 / 400 / 600 / 900** 四档 —— 正文 300（不是 400！），数据 400，display 600，巨型数字 900。
- 字距：几乎所有文本 `-0.225px`（@1440）；display 级 `-7.5px`。以 rem 计 = `-0.3rem` 统一值，随根字号等比缩放，等价于小字 **−0.015em**、大字 **−0.033em**。
- 行高：正文与导航 `lh = font-size`（比值 **1.0**，几乎无行距）；display 级 **0.8**（157.5/126，负行距，字叠字）；巨型数字 1.0。

**根字号是核心机制**：`html { font-size: 100vw / 1920 }`。
- @1440 → 实测 `0.75px`（1440/1920 = 0.75）
- @390 → 实测 `0.203125px`（390/1920 = 0.203）

即全站以「1920 设计画布」为单位，1rem = 0.05208vw。所有尺寸（字号、间距、圆角）都是 7.5 的倍数 @1440，实质是一套 **7.5px 基准的等比缩放体系**。

**字号阶梯（桌面 1440）**

| 实测 px | rem | 设计 px(1920) | 字重 | 行高 | 用途 |
|---|---|---|---|---|---|
| 622.5 | 830 | 830 | 900 | 1.0 | 巨型数字（滚动百分比 / 序号 01 02 03） |
| 157.5 | 210 | 210 | 600 | 0.8 | About 段声明大字（分段逐词揭示） |
| 21.75 | 29 | 29 | 400 | 0.9 | 邮箱 / 关键信息 |
| 15 | 20 | 20 | 300/400 | 1.0 | 说明文字、人名 |
| 13.5 | 18 | 18 | 300/400/600 | 1.0 | **正文主级**、导航、链接 |
| 12 | 16 | 16 | 300/400 | 1.0 | 序号「N.」、社交链接 |
| 10.5 | 14 | 14 | 300/400 | 1.0 | 段落标签 `( about. )` / `( works. )` |
| 9 | 12 | 12 | 300 | 1.0 | 时钟 / 最小元信息 |

阶梯比值：210/29 = 7.2；29/20 = 1.45；20/18 = 1.11；18/16 = 1.125；16/14 = 1.14；14/12 = 1.17。**这是一套"两个维度"的阶梯**：UI 细节密集在 12–20 设计 px（比值 1.1–1.45，非常密），然后一次性跳到 210 / 830 的巨型 display。中间（24–200）**完全空缺** —— 这是本站视觉语言的关键：没有 h2/h3 中量级，要么小到 20px 要么大到 210px。

**移动端（390）**：root `0.203125px`；`.hero__title` 实测 `16px`；文档滚动高 8127px（桌面 9294px）。移动端不是等比缩小的桌面，字号被单独放大（16px 级），否则会不可读 —— 说明「100vw/1920」体系在移动端必须被覆盖。

### 2.3 间距 / 栅格 / 最大宽度

- **无 max-width 容器**：`body` 宽 1425px（1440 减去滚动条），内容直接按视口宽度排。
- Section 内边距（实测，@1440）：about `60 / 97.5`；awards `225 / 300`；expertise `198.75 / 138.75`；form `142.5 / 0`。全部是 7.5 的整数倍（8 / 13 / 30 / 40 / 26.5 / 18.5 rem）。
- Section 高度：hero **2070**（sticky 900 视觉层）、about **2700**、awards **1148**、works **900**、expertise **965**、form **829**、footer canvas **1189**。整页 **9294px @900 视口 ≈ 10.3 屏**（移动 8127px）。
- 布局：全部 `display: block` —— **没有 flex/grid 多列栅格**，用绝对定位 + 单列块流构图。
- 边框：几乎无边框；层次靠底色切换（about 段整段反色为 `#10120f`）。

### 2.4 圆角 / 阴影

- 圆角只有 4 档，全部为 7.5 的倍数：`45px`（=60rem）、`37.5px`、`22.5px`、`7.5px`。
- **全站 0 处 box-shadow**。深度完全不存在 —— 页面是纯平面的，唯一"立体"来自 WebGL canvas。

## 4. 动效

- **库**：**Lenis**（平滑滚动，页面含 `lenis` 字样）+ **three.js**（4 个 canvas：1425×900 ×3、1425×1510）。无 GSAP / Framer / Swiper / Barba。
- **滚动模型**：`position: sticky` 钉住 hero（不劫持原生滚动）；移动端改用 `.scroll-container` 内部滚动。导航固定。
- **过渡曲线**：**全站一条曲线** `cubic-bezier(0.11, 0.82, 0.39, 0.92)` ——
  - `transform` 0.8s
  - `color` 0.8s
  - `all` 0.5s
  - `opacity` **3s**（极长的淡入，用于大图/段落进场）
  - 另有 `opacity 0.3s ease` / `color 0.3s ease` 两处"即时反馈"例外
  - 曲线特征：起步极快（x1=0.11, y1=0.82 瞬间到 82%）、尾段缓慢 —— 是"急停式"而不是常见 ease-out
- **时长分层**：0.3s（微反馈）→ 0.5s（通用）→ 0.8s（位移/变色）→ 3s（大幅淡入）。跨度 **10 倍**。
- **字母动画**：每个字符 3 份副本（DOM 重复），hover 时做垂直滚动置换 —— 这是本站最主要的交互动效。
- **CSS keyframes**：仅 `pulse 1s ease infinite`。
- **canvas 动效**：hero 显示字由 WebGL 绘制（DOM 中的 `h1.hero__title` 实测只有 13.5px / 196×45，真正的巨型字在 `1425×900` canvas 上）—— 滚动/悬停效果在 GPU 层完成。

## 5. 它"为什么好"（3 条可迁移原则）

1. **用「100vw/1920」把整站变成一个等比缩放的画布，所有尺寸都是同一个数的倍数**。实测 `html{font-size: 100vw/1920}`（1440→0.75px，390→0.203px），于是字号 18/20/29/210、圆角 10/30/50/60、间距 8/13/18.5/26.5/30/40 **全部是同一 rem 体系的整数**，缩放时比例永不破。迁移规则：**先定一个设计画布宽（如 1920px）并把 1rem 定义成 `100vw / 画布宽`，此后所有 magic number 都写成 rem 整数 —— 你在任何视口下得到的是同一张画，而不是同一堆断点**。（注意：移动端必须单独覆盖字号，否则 18 设计 px 会缩成 3.6px。）

2. **从阶梯里抽掉中量级，只保留「极小」和「极大」两端**。实测只有 8 级字号，UI 细节挤在 12–20 设计 px（比值 1.11–1.45，非常密），然后直接跳到 210 与 830。没有 h3/h4 这类 30–80px 的中间态。结果是页面要么在读小字，要么在被一个大字砸中 —— 层级不需要任何高亮色或粗体来强调。迁移规则：**删掉 24–100px 所有字号；小字之间用 1.1–1.2 的微差靠字重/颜色区分，强调时直接跳到 5–10 倍**。

3. **全站只锁一条非标准缓动 `cubic-bezier(0.11, 0.82, 0.39, 0.92)`，并用时长跨度（0.3/0.5/0.8/3s）制造节奏**。曲线本身瞬间到 82% 再长尾减速（"急停"），所有 transform/color/all 共用；大幅淡入拉到 3s。迁移规则：**别为不同组件选不同曲线；选一条有个性的曲线，只用「时长 5–10 倍差」区分轻重**（微反馈 0.3s / 常规 0.5–0.8s / 大进场 3s）。

## 6. 不能照抄的地方

1. **行高 1.0 + 字距 −0.015em 在拉丁文里成立，放进 CJK 就是灾难**。实测正文 `15px/15px`、导航 `13.5px/13.5px`（行高比 1.0）；汉字在 1.0 行高下上下粘连，且 CJK 不允许负字距。照抄这条必须先推翻。
2. **Hero 的大字被画进 WebGL canvas**。`h1.hero__title` 在 DOM 里只有 `13.5px / 196×45`，肉眼看到的巨字由 `1425×900` canvas 渲染 —— 于是：无法选中复制、无 SEO 权重、屏读器读不到、字体加载失败时无法回退、低端机 GPU 掉帧。这是作品集型站点的奢侈，产品站不能学。
3. **8 级阶梯里缺 24–200px，导致"中间信息"无处安放**。实战中价格、条款、表单标签、表格、多级标题都落在 24–100px 区间，照这套阶梯只能被迫塞进 20px 或拉到 210px，产品界面会立刻崩。它是"个人品牌 + 一句话宣言"的专用尺子。
4. **正文 300 字重 + 13.5px（等效设计 18px）+ 灰白 `#f5f5f5` on `#10120f`**：细字重在小尺寸下对比度实测观感很弱，深底上更薄。这是"高级感"的代价 —— 正文可读性低于常规 400 字重方案，长文本阅读会累。
5. **四角元信息（12% / 01:56 / scroll 提示）依赖绝对定位铺满视口**，在 `h-[100svh]` 与移动浏览器地址栏收缩时会错位；本站移动端改用内部滚动器才稳住，改造成本高。
6. **动效依赖 1870 个 span 的三倍字母复制**（`aboutaboutabout`）。DOM 体量 = 文本长度 × 3，加上 4 个 canvas，2297 个节点。对 SEO 与屏读器是噪声（重复文本会被读三遍），也不适合任何带内容的 CMS 站点。
