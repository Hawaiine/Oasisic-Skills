# srg.ava-digital.site 深度拆解

> 渲染方式：真实 Chromium 渲染（CDP）。桌面 1440×900，移动 390×844（DPR 2），实测 2026-11-05。
> 站点栈：**Taptop**（`<meta name="generator" content="Taptop">`，俄系站点构建器；class 名形如 `section--u-i2zzwr1e`，随机 ID 生成）+ Webflow 式字体加载器（`html.wf-ibmplexmono-n4-active …`）+ **GSAP / ScrollTrigger / Lenis / three.js / Swiper**（五者均在页面字符串中命中）。
> 滚动：原生滚动可用，`html` 带 `lenis` 类（平滑滚动）；8 个 `position:sticky` 元素承担钉住段。
> 注意：`<html lang="ru">` 而 URL 是 `/en` —— 英文版的语言标记没改（见第 6 节）。移动端文档比桌面更长（20236px vs 19086px）。

## 2. Token 实测

### 2.1 字体

- **两族分工，互不越界**：
  - `Aeonik Pro`（Regular / Medium / Bold）—— 所有标题、导航、正文
  - `IBM Plex Mono`（Regular / Medium）—— 所有元信息：`[ projects ]`、`contact us`、`friends@ava-digital.ru`、`100%`、`Learn more`
  - （另有 `Times New Roman` / `Arial` 出现在少数节点，是未覆盖的默认回退，属瑕疵）
- 字重：**300 / 400 / 500 / 700** 四档。display 用 700/500，正文 400，最小元信息 300。
- `text-transform: uppercase` 是主设定 —— 导航、按钮、区块标题、mono 元信息全部大写（实测 `tt=uppercase` 覆盖 12.67–32.36px 全段）。
- 字距：拉丁大写统一 **−0.03em**（32.36 → −0.971；28.85 → −0.865；21.67 → −0.650；12.67 → −0.380）；mono 与小字 `normal`。
- 行高：**大多数标题 `1.0`**（32.36/32.36、28.85/28.85、21.67/21.67、15.26/15.26），少数压到 **0.9**（21.67/19.51、26.01/23.41、24.375/20.25）；mono 小字 1.2；无 `1.5` 以上的行高。

**根字号**：**标准 16px**（桌面与移动都是），不是流式。这是本批 4 站里唯一不玩 `vw` 缩放根字号的站点。

## 4. 动效

- **库**：**GSAP + ScrollTrigger**（滚动驱动）、**Lenis**（平滑滚动，`html.lenis`）、**three.js**（1 个 canvas）、**Swiper**（review 轮播）。五者同时在场，是本批 4 站里技术栈最重的一个。
- **滚动模型**：原生滚动 + 8 个 `position:sticky` 钉住层；Lenis 提供惯性。
- **过渡曲线（实测去重）**：
  - `0.3s ease` / `0.5s ease` / `0.6s ease` / `1s ease` —— 通用（多数 hover）
  - `0.6s cubic-bezier(0.83, 0, 0.17, 1)` —— **自定义曲线**，接近 ease-in-out 的极端对称版（用于展开/转场）
  - `2s cubic-bezier(0.25, 0.46, 0.45, 0.94)` —— 长时缓出（大图/视频淡入）
- **keyframes**：仅 **`noise 0.2s steps(10)`** —— 胶片颗粒噪点动画，`steps(10)` 逐帧跳（印刷/录像带质感）。
- **媒体驱动**：**17 个 `<video>`**（全部 `muted` + `loop`，源为 `*_1920.mp4`；`autoplay` 属性未设但 JS 调用 `play()` 播放，hero 一个实测 `paused=false`，其余按进入视口触发）+ **384 张 `<img>`** + 1 canvas。
- 预加载：右上角 `0%` → `100%` 进度（截图实测有 12% / 100% 两个状态）。

## 5. 它"为什么好"（3 条可迁移原则）

1. **双族硬分工：人文族管内容，等宽族管元信息，两者永不混用**。实测 `Aeonik Pro` 只在标题/导航/正文（15.26–32.36px），`IBM Plex Mono` 只在方括号标签、邮箱、百分比、`Learn more`（12.67–16.33px，131 处）。结果是不需要图标、不需要彩色，读者一眼就能分辨"这是内容"还是"这是系统标注"。迁移规则：**选 1 个人文无衬线 + 1 个等宽，规定等宽只允许用于编号/标签/数据/单位，且强制 uppercase；任何一处越界都算错**。

2. **字号封顶 32px，用"大写 + −0.03em 字距 + 行高 1.0"换取密度，把视觉重量外包给全幅媒体**。实测最大字级 32.36px（只有 2 处），正文 15.26px，标签 12.67px；而行高几乎全是 1.0，字距统一 −0.03em。于是满屏都是紧排的大写小字，冲击力来自 17 个 1920p 视频和 384 张图，而不是排版。迁移规则：**如果你有媒体预算，把 H1 从 96px 降到 32px 并改成 uppercase + −0.03em + lh1.0，同时把 hero 换成全幅视频 —— 视觉重量立刻从"排版炫技"变成"内容本身"**（没有媒体预算就不要走这条路）。

3. **用三档底色（浅灰米 / 浅一档 / 深灰）在 12 个长 section 之间制造节奏，完全不用卡片、描边或阴影**。实测 `#dad9d3`（hero/team/faq）→ `#e9e8e2`（award/benefit）→ `#323232`（program/review/photo）交替出现，全站 0 处 `box-shadow`、唯一圆角 3px。长页面因此有"章节感"而没有组件感的廉价。迁移规则：**长页面先决定 3 个底色和它们的出现顺序，用整段换底代替分隔线/卡片阴影；圆角压到 ≤4px，阴影清零**。

## 6. 不能照抄的地方

1. **`<html lang="ru">` 挂在 `/en` 英文页上**（实测）。屏读器会用俄语发音读英文内容，搜索引擎语言判定也会错。任何多语言站点都不该复制这种"只换文案不换 lang"的做法。
2. **展示性文字大量依赖图片/视频（384 img + 17 video）**。实测 DOM 里最大字号只有 32.36px，`hero` 的"WE ARE"视觉冲击由全幅视频提供 —— 这意味着标题很可能不可选中、不被抓取、屏幕阅读器读不到顺序。信息型站点照抄会直接损失 SEO 与可访问性。
3. **正文 15.264px / 主标签 12.669px + 全大写 + 负字距 + 行高 1.0**：拉丁小写在大写化后仍可读，但 **CJK 不能用**（无大小写概念、禁负字距、行高 1.0 汉字会粘连）。中文化必须整体重设，不能只换字体。
4. **17 个 1920p 视频的带宽/电量成本**。全部 `muted loop` 且由 JS 触发播放，没有 `poster`、没有 `prefers-reduced-motion` 分支、没有清晰度降级。弱网、省流量、低端 Android 会崩成一排空框（这也解释了为什么移动端文档反而更长：媒体占位更高）。
5. **Taptop 生成器的随机 class（`section--u-i2zzwr1e`、`video--u-ix0e4tc8k`）不可维护**。任何样式改动都得靠覆盖，无法建立 token 层；想迁移到自己的代码库等于重做。这类站只能当"视觉参考"，不能当"实现参考"。
6. **全站无阴影 + 唯一圆角 3px + 无卡片** 的组合，只在"全幅媒体 + 长滚动叙事"里成立。放进后台/表单密集的产品界面，会失去所有层级手段（连 `#f7f7f7` 的浅卡片都没有阴影可依托，浮层无处安放）。
