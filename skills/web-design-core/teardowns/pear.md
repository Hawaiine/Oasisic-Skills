# pear.no 深度拆解

> 渲染方式：真实 Chromium 渲染（CDP）。桌面 1440×900 DPR1，移动 390×844 DPR1，实测 2026-11-05。
> 站点栈：**自研 scroll orchestration**（未检出 GSAP / Lenis / Framer / three 打包字符串，但 `webgl` 可用且页面上有 5 个 canvas）+ 3 个全屏 `1440×900` canvas + 2 个离屏纹理 canvas。2 个 `<video>`，1 张 `<img>`。
> **截图限制（诚实标注）**：文档高 48150px（移动 61612px）≈ 53 屏，内容全部挂在 `.pin{position:sticky; height:900px}` 里的 **10 个 900px 定高绝对定位场景层**（`.nvs` / `.faq` / `.fly-w` / `.ft` / `.cf` / `.fin`），按滚动进度显隐。实测逐点扫描（frac 0 / .02 / .05 / .1 / .2 / .35 / .5 / .65 / .8 / .9 / .95 / .98 / 1.0）时，**除首屏与页尾外每帧都是 100% 纯色 `rgb(11,10,9)`**（WebGL 场景层未激活或渲染超时），且 CDP 截图在 WebGL 重绘期间反复超时（连续 `Page.captureScreenshot timed out`）。
> 因此：**桌面只拿到首屏与页尾 3 张有效截图，中间滚动段标注为"渲染失败"**；移动端 4 张全部有效（移动端 WebGL 负担较低，未超时）。token 全部来自 computed style 实测（有效）。

## 2. Token 实测

### 2.1 字体

**3 族 5 字阶，全部自托管定制字体**：
- `Flecha L` / `Flecha M` / `Flecha S` —— 衬线展示族，三档光学尺寸（L 用于 66–117px，M 用于 26px，S 用于 20–24px）
- `GT Standard L` —— 无衬线正文（12.8 / 15.8px）
- `GT Standard Mono` —— 等宽元信息（8 / 9 / 11 / 12.16px，全部 `uppercase` + 正字距 1.6–1.98px）

**字重只用 300 / 400 / 500 三档**：展示字 300（不是 400），正文 400，等宽标签 500。

**字距规律（关键差异）**：
- 展示字（Flecha）：**负字距 −0.024em**（116.78 → −2.803；66.24 → −0.994；26.22 → −0.524；20 → −0.4）
- 等宽标签（Mono，uppercase）：**正字距 +0.16~0.22em**（8px → 1.6px = +0.2em；9px → 1.8px = +0.2em；11px → 1.98px = +0.18em；12.16px → 0.4864px = +0.04em）
- 正文（GT Standard）：`normal`

**行高**：展示字 **1.0–1.04**（116.78/121.46 = 1.04；66.24/64.92 = **0.98** — 负行距）；正文 1.26（15.8/19.85）、1.32（12.8/16.85）；等宽标签 1.0–1.68（8/12 = 1.5；9/9 = 1.0；11/16.5 = 1.5；12.16/20.46 = 1.68）。

### 2.3 间距 / 栅格 / 最大宽度

- **无 max-width 容器**（实测 `maxW: []`）。
- **无常规 section 结构**（实测 `sections: 1`）—— 48150px 全部由 `.stage`（relative, 48150px）内的 10 个 900px 绝对定位场景层堆叠而成。
- Grid：只用于微型图标（`3.875px 3.875px`、`18.0156px`、`21.0312px`），**没有内容栅格**。
- 布局模型：`.pin{position:sticky; height:900px; background:#0b0a09}` 钉住视口，10 个场景层在其中 `position:absolute; height:900px` 轮换 —— 即"**一个钉住的舞台，场景层按滚动进度切换**"。
- 文字宽度（估算自 DOM 几何，非容器约束）：FAQ 问题 26.22px 的容器约 480px 宽（页宽 33%）；正文明细约 620px（43%）。**内容永远只占页面 1/3–1/2 宽**。

### 2.4 圆角 / 边框 / 阴影

- **圆角 6 档**：`50%`（17 处，圆形）、`999px`（7 处，胶囊按钮）、`22px`（2 处）、`5.25px`（6 处）、`4px`（3）、`3px`（3）。**比第一批 4 站丰富** —— 有小圆角（3–5.25）也有胶囊（999）和全圆（50%），唯独缺 8–16px 的中圆角。
- **边框全部是 1px 白色 alpha**：`rgba(255,255,255,0.1)`（5 处）、`0.3`（2）、`0.2`（1），另有 1 处 `rgba(29,28,25,0.3)`（深色描边）。
- **阴影只有 2 个，且都是 inset**：`rgba(6,20,46,0.12) 0 1px 6px inset`（3 处，凹陷感）、`rgba(255,255,255,0.16) 0 1px 0 inset, rgba(0,0,0,…)`（1 处，顶高光 + 底影）。**没有任何外阴影**。

## 4. 动效

- **库**：**未检出**任何已知库字符串（gsap / ScrollTrigger / lenis / three / PIXI / framer / barba / swiper 全部不在 `outerHTML` 中）—— 但页面有 5 个 canvas 且 WebGL2 可用，说明是**自研 WebGL 渲染器 + 自研滚动编排**（或被极端混淆）。这是一个重要发现：**顶级作品站不一定用 GSAP**。
- **滚动模型**：`position: sticky` 钉住 `.pin`（900px）+ 绝对定位场景层按进度显隐。原生滚动可用（`scrollY` 实测正常）。
- **过渡曲线（实测去重，按出现次数排序）**：
  - **`0.52s cubic-bezier(0.22, 1, 0.36, 1)`** —— 主曲线（出现最多）
  - `0.42s cubic-bezier(0.22, 1, 0.36, 1)` —— 同曲线，短时长
  - `0.64s / 0.76s / 0.38s` 组合，前两段用 `cubic-bezier(0.22, 1, 0.36, 1)`，末段 `linear`
  - `0.45s ease`、`0.38s linear` —— 少量例外
  - **曲线特征**：`cubic-bezier(0.22, 1, 0.36, 1)` 是标准 **easeOutQuint 类**（快起长缓），无过冲 —— 与第一批 digilab / nfinitepaper 的"带过冲"曲线（y1=1.08）形成鲜明对比：pear 要"锐利停止"，那两站要"轻微弹性"。
- **keyframes（实测 3 个，时长都很长）**：
  - **`shine 7s cubic-bezier(0.22, 1, 0.36, 1)`** —— 7 秒光泽扫过
  - **`cross 0.72s`** —— 交叉淡入
  - **`cfArc 9s ease-in-out`** —— 9 秒弧形运动（场景转场）
  - 三个动画时长 0.72 / 7 / 9 秒，跨度 12.5 倍，全部用于 WebGL 场景层而非 UI。
- **媒体驱动**：5 canvas + 2 video + 1 img —— 视觉几乎 100% 由 canvas 承担。

## 5. 它"为什么好"（3 条可迁移原则）

1. **三套并行字号系统，各管一件事，永不混用**。实测：展示族 Flecha 占 20–116.78px（负字距 −0.024em，行高 0.93–1.04）；正文族 GT Standard 占 12.8–15.8px（字距 normal，行高 1.26–1.32）；等宽族 GT Standard Mono 占 8–12.16px（**全部 uppercase + 正字距 +0.16~0.22em**，行高 1.0–1.68）。三套阶梯的区间完全不重叠，靠"字号区间 + 字距正负 + 大小写"三重信号区分角色，而不是靠颜色或粗细。迁移规则：**不要做一条从 8px 到 120px 的统一阶梯；做三条互不重叠的阶梯（展示负字距紧行高 / 正文零字距常规行高 / 等宽大写正字距），并在任何组件里严格限定每一层只能用哪一套。**

2. **单色系统靠白色 alpha 四档做全部层次，实心色只用 4 个**。实测实心色：`#0b0a09`（底）、`#ffffff`（主字）、`#fffaea`（暖白强调）、`#2e2109`（深棕强调）；其余全部是 `rgba(255,255,255, 0.1 / 0.224 / 0.34 / 0.62)` —— 0.1 做描边与微弱填充、0.224/0.34 做面板、0.62 做次要文字。全站无外阴影，只有 2 个 inset 阴影（`rgba(6,20,46,0.12) 0 1px 6px inset`）。迁移规则：**深色主题先定 1 个底色 + 1 个文字色，然后用「文字色的 0.1 / 0.22 / 0.34 / 0.62 四档 alpha」生成全部面板/描边/次要文字；不要引入 5 档灰。描边永远 1px 且用 0.1 alpha。**

3. **同一套钉住舞台（sticky 900px）+ 绝对定位场景层，把 53 屏内容压进 1 个 DOM 容器**。实测 `.stage{position:relative; height:48150px}` 内只有一个 `.pin{position:sticky; height:900px}`，10 个场景层（`.nvs`/`.faq`/`.fly-w`/`.ft`/`.cf`/`.cf-in`/`.fin` 等）都是 `position:absolute; height:900px`，靠滚动进度切显隐。这样做的直接好处：**滚动条长度与实际"阅读进度"解耦**（48150px 只是进度条的像素数，视觉上永远是 1 屏），且场景层可以任意预加载/复用。迁移规则：**需要多场景叙事时，用一个 `sticky h-screen` 容器 + 若干 `absolute h-screen` 场景层，容器高度设为「场景数 × 屏高 × 停留系数」，每个场景层只改 opacity/transform —— 不要用 N 个真实 section 堆出长页面。**

## 6. 不能照抄的地方

1. **53 屏讲 1 件事（48150px @ 900 视口）**：全文只有 FAQ、The Model、商业模式说明几个概念，却用了 53 屏的滚动预算。移动端更夸张 —— 61612px（73 屏）。这是"奖项站"的预算，任何需要被检索、比较、回访的内容都不适用。
2. **桌面端 WebGL 场景在无头/软件渲染环境下完全失效**：实测首屏与页尾之外每帧 100% 纯色 `rgb(11,10,9)`，CDP 截图在 WebGL 重绘期间反复超时（`Page.captureScreenshot timed out` 连续 5 次）。这说明主视觉**完全依赖 GPU 合成的一次性绘制**，没有 DOM 回退、没有静态 poster、没有降级路径。真实用户里的软件渲染、省电模式、远程桌面、老 GPU 全部会看到一片黑。
3. **正文 15.8px / 次要 12.8px / 等宽标签 8–9px**：等宽层最小 8px（`At your service`），11px 的按钮文字，都低于常规可读下限；`uppercase + 0.2em 字距` 让极小的字略微可辨，但这套尺寸只为"装饰性标注"设计，不能承载真正需要读的信息。
4. **负行高（0.98 / 0.93）只适用于纯拉丁短行**：66.24px 标题行高 64.92（0.98）、26.22px 问题行高 24.45（0.93）。汉字在 <1.0 行高下上下相撞，CJK 必须整体重算（通常 +0.2~0.3）。
5. **字体栈是 3 个定制族共 5 个字阶**（Flecha L/M/S + GT Standard L + GT Standard Mono），全部自托管、无 web-safe 等价物。Flecha 是商业字体（GT 家族同厂），替换字体后"负字距 + 0.93 行高"的紧排效果立刻失效，整套排版需要重做。
6. **不检出任何动画库字符串**，说明要么自研（维护成本极高，需自己处理滚动同步、性能、可访问性），要么被混淆到不可审计。生产项目里照抄这个"栈"等于从零实现 Lenis + GSAP ScrollTrigger 的功能。
