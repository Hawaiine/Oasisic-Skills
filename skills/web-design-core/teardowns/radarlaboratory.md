## 4. 动效

- **库**：**three.js + THREE + matter.js**（物理引擎，用于雷达波传播模拟）。
- **过渡**：`0.14s ease` / `0.15s ease` / `0.18s ease` —— **极快**（0.14–0.18s），与前 3 站的 0.5–2s 形成鲜明对比。这是"仪表板响应"的时长，而非"叙事动画"。
- **keyframes 2 个**：
  - `rlDot 2.4s ease-in-out` —— 雷达点闪烁
  - `rlPulse 2.8s ease-in-out` —— 脉冲扩散
  - 都是 2.4–2.8s 的循环动画，与 UI 过渡的 0.14–0.18s 形成"背景慢/前景快"的双速体系。
- **WebGL 实时渲染**：2 个 canvas，0 img / 0 video —— 所有视觉都是 GPU 实时计算，包括电磁波传播、散射、多普勒效应。

## 5. 它"为什么好"（3 条可迁移原则）

1. **用三族字体 + 全大写窄体做"科技仪表板"身份**。实测：Bebas Neue 全大写 w700 做标题（112px H1 + 17.6px 模块标题）、Crimson Pro 衬线做正文（19.44px w600）、Share Tech Mono 等宽做全部按钮/标签/参数（9.6–11.84px，含 w800 的「Start Learning」）。迁移规则：**科技/工具类界面用"全大写窄体标题 + 衬线正文 + 等宽操作层"三族分工，且等宽层字重最大（w800）—— 这样标题像印刷品、正文像论文、操作像终端，三种性质分明**。

2. **UI 过渡极快（0.14–0.18s），背景动画极慢（2.4–2.8s），双速体系制造"仪表板响应感"**。实测过渡 3 条全部 0.14–0.18s ease（点击/hover 即时反馈），keyframes 2 条 2.4–2.8s（雷达点脉冲持续背景循环）。与前 3 站的 0.5–2s 单一节奏完全不同。迁移规则：**工具类界面把 UI 过渡压到 ≤0.2s（操作即时感），把装饰动画拉到 ≥2s（背景氛围感）—— 不要混用一套 0.5s**。

3. **配色模拟物理对象（雷达屏幕），深蓝黑底 + 荧光绿回波 + 橙色警示，零纯白零纯黑**。实测底色 `rgb(13,28,39)` / `rgb(9,18,26)`（深蓝黑），主强调 `#00cc6a` / `#00ff88`（荧光绿），警示 `#ffb347`（橙），最亮文字 `rgb(184,205,216)`（浅蓝灰，不是纯白）。迁移规则：**当界面模拟一个物理对象时（仪表板/显示器/控制台），配色应该复现那个对象的光学特性 —— 雷达屏幕的底是深蓝黑（阴极射线管），回波是荧光绿（磷光体），不是"黑底白字"的抽象 UI**。

## 6. 它"不能照抄"的地方

1. **100% 依赖 WebGL 实时渲染**（2 canvas，0 静态图片/视频），无降级路径。软件渲染、低端 GPU、省电模式下雷达波动画失效 → 页面变成空白面板。
2. **H1 行高 0.88（负行距）只适合 Bebas Neue 窄体**，换字体后字形会重叠。
3. **等宽按钮最小 9.6px**（「GO →」），极限可读性，只适合"标注"而非"阅读"。
4. **荧光绿 `#00ff88` 在深蓝底上对比度极高但刺眼**，长时间盯看会疲劳（这是雷达屏幕的真实特性，但 UI 设计通常避免）。
5. **只有 2 个 section 共 2769px（3.1 屏）**，是单一工具页，不是多概念叙事站。
6. **依赖 matter.js 物理引擎计算雷达波**，带宽 + 计算成本高于静态 SVG/video 方案。
