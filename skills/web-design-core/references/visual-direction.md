# 多方向探索与设计判断

> 方法吸收自 [oil-oil/oil-ui](https://github.com/oil-oil/oil-ui)（MIT），按本 skill 的交付标准重写；完整工作流（截图脚本、评审子代理、生图管线）见其上游仓库，本文件只保留与「Design Brief + 自检」配套的判断层。

## 1. 先定北极星，再谈风格

一句话写清「这一页最想让人留下什么印象」，写不出就说明方向还没定。后面每个决定都要能回指到这句话。

- 好：「像一本被反复翻阅的纸书，而不是一个 App」
- 坏：「简约、大气、科技感」——这三个词不构成决定，任何人写出来都一样

**模糊词必须翻译成参数**（这是最容易漏的一步）：

| 用户说 | 翻译成可执行的东西 |
|---|---|
| 高级感 | 低饱和（S≤35%）、发丝线分隔（1px / α 0.12）、大留白（区块间距 ≥96px）、衬线标题 |
| 科技感 | 深底（L≤8%）、等宽字体点缀、单一冷色强调、数据密度高 |
| 年轻 | 更大字重对比（400 vs 800）、圆角 ≥16px、允许一处高饱和色块 |
| 稳重 | 衬线正文、行长 ≤68ch、无动画或仅 150ms 微量位移 |

## 2. 认品类，拆标杆

先判断这页属于哪类任务，再决定骨架（两者不能反）：

- **说服型**（发布/品牌/展览）：首屏要有主张，容得下一句不在别处说过的话
- **工具型**（后台/编辑器/管理）：首屏就是第一排内容或工作区本身，页头压成一行，不放口号
- **浏览型**（图库/列表/资讯）：首屏要能看到「内容的形状」，即真实条目，不要空状态替代品

拆 2 个标杆站点，每个只取一条能落地的规则（例：「Pear 的标题与正文只用两个字重差，靠字号拉开层级」），写进 Brief §1 的「借鉴什么」。**不要**写「参考 XX 的风格」——那不是决定。

## 3. 三方向对比（用户要求比较时）

最少 3 个方向，且必须在 **≥3 条差异轴**上真正不同，只换强调色不算：

| 差异轴 | 取值举例 |
|---|---|
| 底色明暗 | 近黑 / 暖纸 / 暖白 |
| 字体族类别 | 纯无衬线 / 衬线+无衬线双族 / 等宽点缀 |
| 信息密度 | 16px 基准大留白 / 14px 基准紧凑 |
| 骨架 | 居中单列 / 非对称分栏 / 侧栏+主区 |

每个方向交：一句北极星 + 首屏骨架 + 色板 3 值 + 字体族 + 一句「这个方向牺牲了什么」。**必须写牺牲项**，否则三个方向会趋同。

对比页只需并排 iframe 或三张全页截图，同一份内容、同一视口高度，横向滚动对比；不要做「风格选择器」那种把三种风格混进一个页面的东西。

## 4. 先删减，锁定主角

动手前先回答：这一屏**只能留一个主角**（图/数字/标题/一次交互）。其余元素的作用是让它更突出，而不是与它竞争。

自检三问：
1. 删掉这个元素，页面会变差吗？不会 → 删
2. 这个元素在为北极星服务，还是只是「通常会有」？
3. 首屏有第二个同等重量的视觉重心吗？有 → 拆掉一个

## 5. 参考如何转成决定

看到喜欢的站点，不要抄外观，抄**约束**：

- 它用什么行长？→ 落到 `--measure: 68ch`
- 它的标题与正文差几个字号级别？→ 落到 `clamp()` 的两个端点
- 它的分隔靠线还是靠空间？→ 落到「1px α 0.12 线」或「96px 间距」，二选一
- 它有动效吗？是入场编排还是状态反馈？→ 落到具体时长与曲线

写进 Brief §7「引用依据」，格式：`参考站点 → 提取的约束 → 落到哪个变量`。

## 6. 独立评审（可选，多方向或大改版时）

自己评自己容易只看通过项。要评审就换个上下文，按固定口径打分并**只报证据**：

- 视觉（0–5）：层级是否一眼可读、字体/色板是否统一、是否有模板味
- 任务（0–5）：主要任务在第几屏可完成、是否需要滚动超过 1.5 屏
- 一致性（0–5）：同一语义是否全站同一表现（按钮层级/空状态/错误态）
- 每条扣分必须附「元素 + 实际值 + 期望值」，例如「副标题 13px 与正文 14px 同级 → 应降到 12px 或升到 16px」

总分不作为验收标准，**扣分项是否被逐条处理**才是。

## 7. 不要做的事

- 不要为了「看起来设计过」加装饰：编号、箭头、渐变描边、发光边，都要能回答「它替读者解决了什么」
- 不要三个方向共用同一个首屏骨架再换皮
- 不要在用户没要求比较时输出多方向（那是拖延，不是专业）
- 不要把上游 skill 的脚本/素材整包搬进仓库：本文件只搬判断，工具按需引用上游
